# 自动后期制作

本仓库是一套在本机运行的短视频后期引擎。它从已有画面和一篇完整口播稿出发，完成配音、字幕、选镜、渲染和审片，并把每一次提交留成不可变的任务版本。

它不生成原始视频。画面来自导入的素材，口播来自粘贴稿或一次明确指定的写稿技能。网页只负责操作和确认，任务结构以 `edit-job/v2` 合同为准。

## 适合什么片子

一条任务处理一种语言：中文口播。时间以 1920 ticks 为步长。素材可以一次导入多段，顺序不影响结果。

每个视频在导入时选定角色：

- **商品画面，自由剪辑。** 进入候选镜头库，按句子选择可用片段。
- **固定开头、固定中段或固定结尾。** 保留原声和原剪辑，不裁切，不参与自由选镜。需要填写对应台词，供后续核对。

分析有两种粒度：整段分析，或用本机 PySceneDetect 按场景切出候选窗口。与整稿无关的画面会被排除，不会用来填空。某一句没有可用镜头时，任务停在「缺镜头素材」，列出句号和需求；补素材后新建版本。

选镜模式写在任务意图里：

| 模式 | 行为 |
|---|---|
| `precise` | 按句取窗口，并经过语义和已确认区间约束。未写模式时按此处理 |
| `whole_clip` | 按整段素材的粗相关性选择和拼接 |
| `beat` | 按句子节奏匹配已审阅的素材卡片 |

商品关键词会作为选镜的硬约束。默认配乐、声音和可导入目录来自该任务锁定的账号配置，不由网页上的账号标签推断口播行业。

## 一条任务怎么走

操作在本机网页完成，地址是 `http://127.0.0.1:8760`。不需要手写 JSON。步骤说明见[操作手册](docs/runbooks/auto-postprod-operator-v2.md)。

1. 选择账号配置和栏目，导入素材并标好角色。
2. 选定配音入口。三条入口互斥，提交后不会自动改道。
3. 放入整稿。粘贴稿只做分句；生成稿必须在页面明确选择一个写稿技能。账号、栏目和商品词不会代选技能。
4. 勾选本次需要的色彩预览和付费调用授权，提交。
5. 按界面状态逐段确认。未确认的阶段不会继续。
6. 需要修改时生成新版本。旧版本保持不变。

配音入口：

- **自动配音。** 用账号配置中登记的声音和预设，把整稿连续合成一次。
- **上传现成配音。** 接受 WAV 或 MP3。这一版任务内不再调用语音合成。
- **历史配音。** 只列出曾经试听确认、并且文件校验通过的版本。

整稿的句子顺序就是叙事顺序，分句同时决定镜头段落。生成稿的技能名称、版本和提示词审计字段随任务保存，供之后对照当时实际使用的规则。

## 确认和修订

每一版都要人看过才能往下走。技术检查通过只说明文件和流程完整，不代替内容验收。

| 状态 | 确认什么 | 不过关时 |
|---|---|---|
| 待确认整稿 | 句子拆分和文字 | 不进入配音 |
| 待试听配音 | 实际听到的声音 | 停止，另建版本 |
| 待字幕校对 | 声音和原稿逐句对照 | 声音正确就按原稿修正识别；声音读错就重配。未确认的句子不会自动通过 |
| 缺镜头素材 | 哪一句没有可用画面 | 补充素材后新建版本 |
| 需重配声音 | 哪些句子确认读错 | 改该句文字或换音频，再建版本 |
| 待审阅 | 画面、色彩、声音、字幕、事实、嘴型、切点 | 逐项审阅后再决定是否采用 |

修订都会指向父版本，并按变更路径决定哪些阶段可以复用：

- 改字幕文字只重新烧录字幕，配音、画面分析和选镜沿用。
- 替换一个镜头时选择候选并填写理由。时长保持一致。与其他镜头源窗口重叠的候选必须明确允许并留下记录。
- 配乐可以改音量或更换文件。更换时记录来源和授权说明。署名放在发布文案，不写入画面。
- 整稿文字变化才会重新合成配音。整稿和配音方式不变时，字幕、配乐和换镜修订不重新合成。
- 手动改稿保存为粘贴稿修订，不调用写稿模型。若原版本绑定过技能，修订保留该绑定作为来源记录。

云端调用结果未能确认时，账本保留该次预留和回执，状态为提交未知。这种状态不自动重发。

## 程序怎么分工

调度器负责任务图、数据库、版本、确认门和返修路由。四个本地进程由 supervisor 拉起：调度、MPT、Narrato、Cosy。网页通过调度器的本机接口操作，不直接调用模型。

| 部分 | 位置 | 作用 |
|---|---|---|
| 调度 | `scheduler/` | 任务编排、SQLite、版本、确认和恢复 |
| 画面与配音适配 | `workers/` | MPT、Narrato，以及 Cosy 语音合成 |
| 模型网关 | `providers/` | 统一调用、额度预留和回执账本 |
| 渲染 | `renderer/` | 时间线编译、FFmpeg 渲染和成片校验 |
| 网页 | `ui/` | 导入、确认、审片和修订 |
| 合同 | `contracts/` | 任务、时间线、字幕、镜头库等结构 |
| 配置 | `config/` | 版本、账号登记、文本分档和技能登记 |
| 迁移 | `migrations/` | 数据库结构迁移 |
| 依赖锁 | `locks/` | 可复现安装使用的锁定文件 |
| 脚本 | `scripts/` | 安装、启动、停止和验证。索引见 [scripts/README.md](scripts/README.md) |
| 测试 | `tests/` | 回归测试 |
| 技能与文档 | `.agents/`、`docs/` | 可选用的写稿技能和操作说明 |
| 提交记录 | `submissions/` | 允许修改的范围，以及提交前要写的记录 |

文本模型分档在 [config/ark-text-agent.json](config/ark-text-agent.json)。整稿生成和审片使用不同档。画面描述与文本调用共用任务额度，由网关按请求入账；同一闸门后的重跑不重复计费。选镜先由本机 Clef 排序，再做文字审片。配音和字幕识别在本机进行，只在实际推理时加载，结束后退出。

账号配置在任务第一次提交时锁定散列。之后的修订继续使用这一份。配置文件后来的修改不影响已有任务；要使用新配置，新建任务。登记表在 [config/account_profiles.json](config/account_profiles.json)，引擎本身不绑定某一个账号。

## 运行

目标环境是 Windows。调度和 Narrato 使用 Python 3.12，MPT 使用 Python 3.11，解释器版本记录在 `config/versions.json`。安装使用 `uv` 和 `locks/` 中的锁定文件，上游工作副本放在 `upstream/`，虚拟环境放在 `envs/`。这两处都不进入版本库。

```powershell
scripts/install.ps1
scripts/start.ps1 -OpenUI
```

也可以双击根目录的 `自动剪辑.cmd`。浏览器打开本地页面并带上一次性令牌后即完成登录。FFmpeg 由本机提供，仓库只保留 `tools/ffmpeg/manifest.json`，不包含可执行文件。

克隆这份源码之后，还需要本机的 Python 环境、FFmpeg、声音组件和一份账号配置，才能完成一条真实片子。

## 仓库里不包含的运行数据

以下内容留在运行机器上，由 [.gitignore](.gitignore) 排除：

| 路径 | 内容 |
|---|---|
| `artifacts/` | 导入素材和内容寻址文件 |
| `jobs/` | 任务版本和中间结果 |
| `output/`、`delivery/` | 按审阅状态归类的输出和成片 |
| `state/`、`logs/` | 数据库、进程状态和日志 |
| `envs/`、`upstream/` | 虚拟环境和上游工作副本 |

图片、视频和音频文件不进入版本库。任务之间会按素材散列复用分析结果，因此不能只按目录年龄清理这些运行数据。

## 合同和测试

当前编辑任务的正式结构是 `contracts/edit-job-v2.schema.json`。同目录还有时间线、字幕校对、镜头库、旁白计划和脚本草案等合同。旧的 `edit-job/v1` 任务仍可读取、回放和修订，不会被改写成 v2。

测试在 `tests/`。只读检查和单元测试不加载本机模型。会调用真实模型或写入运行数据的脚本列在 [scripts/README.md](scripts/README.md)，出现在索引里并不表示可以随意执行。

## 提交改动

可以直接查看和克隆。允许修改的源码、合同、测试和说明，通过拉取请求提交，由维护者审阅后合并。没有写入权限时不能直接推送到本仓库。

提交前先按 [submissions/README.md](submissions/README.md) 写好记录，再把记录和改动放进同一次请求。记录模板是 [submissions/record-template.md](submissions/record-template.md)。
