# 可提交的修改

这里登记允许改动、并且准备交给维护者审阅的内容。先写记录，再提交拉取请求。记录和对应改动放在同一次请求里。

没有写入权限时不能直接推送到本仓库。拉取请求由维护者合并后才进入 `main`。

## 可以修改并提交

这些路径里的源码、合同、配置样例、测试和说明可以修改：

| 路径 | 可以改什么 |
|---|---|
| `scheduler/`、`workers/`、`providers/`、`renderer/`、`ui/` | 编排、适配、网关、渲染和本机网页 |
| `contracts/`、`migrations/` | 任务结构定义和数据库迁移 |
| `scripts/`、`tests/` | 安装、启动、验证脚本和回归测试 |
| `docs/`、`submissions/` | 操作说明和本目录的提交记录 |
| `config/` 中已经在仓库里的分档与登记 | 模型分档、技能登记等公开配置。不要加入本机路径、密钥或账号口播稿 |

一次请求只做一件事。合同字段变更要同时改对应测试。说明和程序不一致时，以本次记录里写明的行为为准，并在同一次请求里改掉过时说明。

## 不要放进提交

- 图片、视频、音频和成片
- 密钥、令牌、本机绝对路径和账号口播稿
- `artifacts/`、`jobs/`、`output/`、`delivery/`、`state/`、`logs/`、`envs/`、`upstream/` 里的运行数据
- 行业话术库、产品文案和只在本机使用的组装方案

这些内容留在运行机器上。提交记录里可以写“使用了本地资料”，不要把资料正文贴进来。

## 提交前先写记录

1. 复制 [record-template.md](record-template.md)。
2. 保存为 `submissions/records/年-月-日-短名.md`。短名用小写英文和连字符，例如 `2026-10-16-subtitle-margin.md`。
3. 写清要改的文件、原因、怎么验证、如何回退。记录写完再改程序。
4. 程序改完后，把验证结果补进同一份记录。
5. 拉取请求的说明指向这份记录。没有记录的改动不进入审阅。

记录一旦合并就保留，用来对照当时为什么改。后来的修订另写一份记录，不覆盖已经合并的记录。
